# 从原版 CatWrt 迁移

## 适用对象

本文适用于从原版 CatWrt（项目 `miaoermua/CatWrt`，基于 LEDE）迁移到 CatWrt Next（基于 ImmortalWrt 25.12.2）的用户。

原版需为最后一个版本 v25.8。更老的版本请先升级到 v25.8，或者直接全新刷写 CatWrt Next。本项目不提供自动迁移工具；软件包管理器从 opkg（ipk）更换为 apk（apk-tools v3），两者不兼容。

## 前置条件与迁移前备份

目标磁盘可用容量需不小于 1.1 GB。CatWrt Next 的根分区固定为 1024 MiB；采用保留配置的原地升级时，完整镜像会写入整块磁盘，磁盘更小时分区会超出磁盘范围，设备重启后无法启动。虚拟机请先扩容磁盘再操作。

开始前在原系统的 LuCI“系统 → 备份/恢复”中导出配置，并将备份保存到设备之外。另行记录以下设置，供迁移后核对：

- WAN 类型（DHCP／PPPoE）。
- LAN 地址。
- 端口转发与静态路由。
- 定时任务。
- 已安装的插件及其用途。

## 推荐方式：保留旧盘，新盘全新安装

生产环境优先采用这种方式。原版磁盘保持不动，迁移失败时可以直接切回。

1. 准备一块容量不小于 1.1 GB 的新磁盘或新虚拟机。
2. 从本项目 Releases 下载与启动方式（EFI／BIOS）对应的 `img.gz` 镜像，刷写前核对发布页提供的 SHA256。
3. 将新盘接入设备，或把新虚拟机接到与旧路由隔离的测试网络，完成首次启动。
4. 按迁移前的记录，在 CatWrt Next 中重新配置 WAN、LAN、防火墙、端口转发、静态路由、定时任务和必要的插件。
5. 逐项核对“迁移后检查清单”，确认管理面与 WAN 访问均符合预期后，再断开旧盘并切换为新盘。

直通网卡或双网口设备上，先按 MAC 地址和驱动确认 LAN／WAN 对应的物理网口，再接线和配置。不要照抄旧系统的 `eth` 编号：新底座的内核与网卡命名可能不同，照抄会把 LAN 和 WAN 接反，导致设备失联或管理面暴露。

## 实验性方式：原地 `sysupgrade`

> 仅用于非生产测试。跨底座保留配置不属于稳定支持范围。

风险：

- 防火墙从 fw3 更换为 fw4（nftables）。旧规则、插件写入的 iptables 规则和自定义脚本不会自动转换，可能出现规则失效或入站暴露。
- 磁盘可用容量需不小于 1.1 GB，否则保留配置升级可能写入失败，设备重启后无法启动。
- opkg 插件不会保留。原版软件源全部失效，需要重新安装兼容的 apk 软件包。

基本步骤：

1. 完成“迁移前备份”，并确认原版配置备份已复制到设备之外。
2. 下载与启动方式对应的 squashfs `img.gz`，核对 SHA256。刷写使用 `img.gz`，不要使用虚拟机磁盘格式 `qcow2`。
3. 将镜像传到原版设备，执行 `sysupgrade -v <镜像>`，保留配置升级。
4. 等待刷写和重启完成，期间不要断电。重启后立即按检查清单核对。如果长时间停在 `Waiting for root device`，通常是磁盘容量不足或 sysupgrade 未写入配置，需要重新刷写。

## 离线安装软件包

设备尚未接入外网时（例如需要先安装网络认证类软件包），直接对单个 `.apk` 路径执行 `apk add --no-network <文件名>.apk` 仅在软件包自身带有可信内嵌签名时生效。本项目自有软件源导出的 `.apk` 自身不含内嵌签名，必须与同一发布标签、同一架构的签名索引 `packages.adb` 放在设备同一目录中按仓库方式安装，完整步骤与命令见[自有软件源：离线安装](packages.md#离线安装)。

安装前可用 `sha256sum` 核对传输完整性，但 SHA256 不能替代签名校验。遇到 `UNTRUSTED signature` 时不要使用 `--allow-untrusted`（它会跳过签名校验），也不要从不可信介质导入新公钥；如有未安装的依赖包，需连同依赖所属仓库的 `packages.adb` 一并准备。

## 迁移后检查清单

- [ ] LAN 地址与主机名是否符合预期。
- [ ] WAN 是否正常拨号或获取到地址。
- [ ] 是否按 MAC 地址核对并绑定了正确的 LAN／WAN 网口。
- [ ] DHCP 客户端能否获取租约。
- [ ] DNS 解析是否正常。
- [ ] 防火墙端口转发是否生效。
- [ ] 管理面（LuCI、SSH、TTYD 等）是否仅限预期内网访问，WAN 入站是否默认拒绝。
- [ ] 静态路由与定时任务是否保留并正常运行。
- [ ] LuCI 语言是否符合预期。
- [ ] root 密码是否已设置或修改；如果仍是原版的默认密码，立即修改。

## 不兼容项

- 软件包管理器从 opkg（ipk）更换为 apk（apk-tools v3）。原版软件源全部失效，已安装的插件（包括手动安装的插件）不会带过来，需重新安装兼容的软件包。
- 本固件不提供原版特有插件，例如 easytier、雷神加速器、校园网套件等。
- 本项目不提供自动迁移工具。
- 不支持从 v24.9 及更早版本保留配置迁移。

## 回滚

### 首次迁移失败回滚

如果采用“保留旧盘，新盘全新安装”，直接切回未改动的原版磁盘。新盘上的配置可以保留，待排查后再继续迁移。

如果采用了原地 `sysupgrade`，需要重新刷回原版 CatWrt v25.8 镜像：从可信来源下载镜像，核对 SHA256 后刷入，再恢复迁移前导出的原版配置备份。回滚会丢失迁移期间在新系统中做的配置修改。

### CatWrt Next 日后升级失败回滚

`cattools` 在每次升级刷写前会先执行 `sysupgrade -b`，将当前配置导出到 `/tmp/catwrt-backup-<版本>.tar.gz`，备份失败时拒绝继续。`/tmp` 在重启后会被清空，因此升级前必须先用 `scp` 或其他方式把备份复制到设备之外。

需要回滚时：

1. 下载上一版本 CatWrt Next 的对应镜像，核对发布页提供的 SHA256。
2. 刷入该镜像。是否保留当前配置按故障情况决定；若配置已损坏，选择不保留。
3. 设备启动后，通过 LuCI“系统 → 备份/恢复”或 `sysupgrade -r <备份文件>` 恢复升级前复制到设备之外的配置备份。
